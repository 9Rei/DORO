DORO — оптимизация Firebase + Golden
Сборка: 16.11.2026

ЧТО ИЗМЕНЕНО

1. script.js
- Кэш списка пользователей живёт 24 часа вместо 5 минут.
- Обычная синхронизация после срока кэша запрашивает только документы с updatedAt после последней синхронизации (listUsersSince), если есть кэш.
- Полная загрузка всех пользователей выполняется при первом запуске/ручном обновлении и примерно раз в 7 дней, чтобы обнаруживать удаления и старые документы.
- Загрузка списка ролей больше не вызывает принудительную повторную загрузку всей коллекции users.
- Изменение профиля не запускает полное чтение всех пользователей.
- В окне Golden номер можно скопировать; добавлен fallback копирования для браузеров без Clipboard API.

2. content-store.js
- Индекс тем кэшируется в localStorage на 6 часов.
- В localStorage сохраняются метаданные тем без больших полей content, чтобы не переполнять хранилище браузера.
- Кэш индекса сбрасывается после создания, обновления, удаления темы и после записи лениво мигрированного текста.

3. index.html + style.css
- Убрана кнопка перехода в Сбербанк.
- Окно оплаты предлагает ручной перевод по номеру телефона через СБП, копирование номера и отправку заявки после перевода.
- Сохранена ручная проверка заявки администратором; нажатие кнопки само по себе не активирует Golden.

4. Остальные файлы
В ZIP сохранены остальные файлы пакета стабилизации профилей/входа/Golden, чтобы пакет можно было распаковать как полный набор файлов проекта.

СОХРАНЕНИЕ ДАННЫХ
- Код не очищает Firestore и не переименовывает документы.
- Не удаляйте коллекции users, roles, payment_requests или topics.
- Не сбрасывайте профильные кэши вручную и не запускайте миграции базы.
- Перед загрузкой сделайте резервную копию текущего GitHub-репозитория.

ВАЖНО ПРО ЛИМИТ READS
- Это уменьшает повторные чтения на том же устройстве, но не убирает чтение при первом посещении сайта новым устройством/браузером.
- Полная загрузка списка пользователей всё ещё читает все документы users, когда пользователь вручную нажимает «Обновить» и при полной сверке примерно раз в 7 дней.
- Список тем всё ещё читает коллекцию topics при первом посещении и после истечения 6-часового кэша на каждом браузере.
- Для точного определения главного источника расхода нужно посмотреть Firebase Console → Firestore Database → Usage (Reads) и сопоставить пики с посещениями сайта. Не включайте платный тариф ради этих изменений.

УСТАНОВКА
1. Скачайте ZIP и распакуйте его.
2. Сохраните копию текущих файлов GitHub.
3. Сверьте пакет с актуальным репозиторием перед заменой: пакет основан на последнем сохранённом архиве исходников проекта, а не на автоматически опубликованном коммите.
4. Замените файлы в корне репозитория и отправьте один commit.
5. После GitHub Pages deployment проверьте: вход/выход, профиль, список пользователей, существующий Golden, подачу тестовой заявки (не оплачивая) и одобрение заявки администратором.
6. Если увидите ошибку, не удаляйте документы Firestore — пришлите текст ошибки.

Не добавляйте в Firestore Rules allow read, write: if true. Не публикуйте секреты и service-account ключи в репозитории.
