DORO — пакет стабилизации входа, профилей и Golden
Дата сборки: 15.11.2026

ЧТО ИЗМЕНЕНО
1. firebase.js
   - Стабильная инициализация Firebase Auth и явный offline fallback.
   - Обновление API при переходе с анонимной сессии на аккаунт с паролем.
   - Более понятная обработка неверного пароля.
   - Сохранение профиля использует актуальный UID.
   - getMyProfile поддерживает старый формат ID name__GROUP, чтобы находить прежние профили.
   - listAllUsers больше не пропускает старые документы без updatedAt.
   - Автоматическая очистка дублей теперь только диагностирует дубли и ничего не удаляет.
   - Миграция профиля сохраняет облачные поля Golden.

2. script.js
   - Удалён сетевой запрос Golden каждые 3 минуты.
   - Облачная синхронизация Golden выполняется при загрузке/входе и затем не чаще раза в 24 часа.
   - Если поле premiumActive отсутствует в документе или запрос не удался, локальная подписка не отключается.
   - Если в облаке явно premiumActive=false или срок истёк, локальный статус обновляется.
   - При входе профиль Golden сразу синхронизируется.
   - Кэш списка пользователей сокращён с 7 дней до 1 часа.
   - При смене имени/группы профиль и поля Golden переносятся до удаления старого документа; удаление происходит только если старый документ удалось прочитать и новый сохранить.

3. premium.js
   - Убраны дублирующиеся события обновления состояния Golden.
   - Нормализуется сохранённое состояние подписки.
   - Снятие Golden не сбрасывает роль администратора/редактора.

4. roles.js
   - Роли повторно загружаются при смене анонимной Firebase-сессии на реальный аккаунт.
   - Обновление ролей не стирает класс Golden.

5. admin.js
   - После активации/отзыва Golden сбрасывается локальный кэш списка пользователей.

ВАЖНО
- Это пакет исправлений на уровне клиентского кода. Я проверил синтаксис JavaScript, но не мог выполнить полноценный тест против вашей базы Firebase: текущие Firestore Security Rules и настройки консоли в архиве отсутствуют.
- Не удаляйте коллекции users, roles или payment_requests и не переименовывайте документы.
- Перед публикацией сохраните копию текущего репозитория/файлов.
- Не вставляйте в Firestore Rules правило allow read, write: if true — это открывает базу всем.
- Для безопасного администрирования одних CSS-классов/roles-документов недостаточно: операции оплаты и выдачи Golden в идеале должны быть защищены Firestore Rules и/или Cloud Functions с проверкой admin custom claims.

КАК УСТАНОВИТЬ
1. Скачайте DORO_stable_patch.zip и распакуйте в отдельную папку.
2. Сначала сделайте резервную копию текущего репозитория GitHub (Download ZIP или отдельная ветка).
3. Замените в репозитории пять файлов из пакета: firebase.js, premium.js, script.js, admin.js, roles.js. Остальные файлы не меняйте.
4. Сделайте один commit, дождитесь GitHub Pages deployment и проверьте сайт в приватном окне браузера.
5. Проверяйте сначала вход, затем открытие профиля, список пользователей, Golden, и только потом админскую активацию/отзыв.
6. Если ошибка появляется, пришлите точный текст из Console и Firebase Rules — не удаляйте пользовательские документы.
