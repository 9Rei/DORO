# DORO — снижение нагрузки Firebase

## Что изменено

- Список тем кэшируется в браузере на 7 дней вместо 6 часов. Повторные одновременные вызовы `loadAllTopics()` объединяются в один запрос.
- Текст темы, который уже был открыт, сохраняется локально до 7 дней (только если размер меньше 90 КБ). Следующие открытия не требуют повторного чтения документа.
- Открытие старого материала с GitHub больше не запускает автоматическую запись в Firestore. `syncToDb()` остаётся доступной для явного вызова, но чтение само по себе ничего не записывает.
- Список пользователей берётся из локального кэша; обычная инкрементальная проверка остаётся после истечения кэша. Полная сверка выполняется раз в 30 дней либо по ручному обновлению. Если инкрементальный запрос не удался, код не запускает полный скан всей коллекции автоматически.
- Список ролей для бейджей пользователей кэшируется на 24 часа, чтобы не читать коллекцию `roles` на каждом старте.
- Персональная роль кэшируется на 6 часов, одинаковые одновременные проверки объединяются; при смене Firebase UID роль перечитывается. Серверная проверка прав не заменяется клиентским кэшем.
- Состояние заявки Golden кэшируется на 60 секунд для интерфейса. Перед созданием новой заявки выполняется свежая проверка, а повторные нажатия объединяются.
- Сохранены существующие коллекции и форматы документов. Код не удаляет пользователей, роли, подписки, сроки или заявки.

## Установка

1. Скачайте архив `DORO_Firebase_Low_Load_Rebuild.zip`.
2. Сохраните текущую версию сайта отдельно как резервную копию.
3. Замените файлы в репозитории GitHub файлами из архива, сохраняя структуру проекта.
4. Дождитесь публикации GitHub Pages и откройте сайт в приватной вкладке для первичной проверки.
5. Проверьте вход старого пользователя, отображение Golden, список пользователей, роли редактора/администратора и создание тестовой заявки (не оплачивая её).

## Важные ограничения

- Изменения файлов сами по себе не изменяют данные Firestore и не требуют миграции коллекций.
- Существующая схема `topics` хранит метаданные и текст в одном документе. При первом холодном запросе списка Firestore всё ещё возвращает документы коллекции; чтобы убрать и эту нагрузку, нужна отдельная коллекция `topic_index` и контролируемая миграция метаданных.
- Кэш браузера может быть старым до истечения TTL. Для списка пользователей предусмотрено ручное обновление; для изменений материалов редакторские методы инвалидируют локальный индекс и текстовый кэш на текущем устройстве.
- Firestore Security Rules не изменялись. Нельзя ослаблять правила ради уменьшения чтений. Для окончательной проверки безопасности нужны актуальные Rules проекта.
- Архив подготовлен из файлов проекта, доступных в этой сессии, включая прошлые локальные правки интерфейса. Он не опубликован в GitHub автоматически.
