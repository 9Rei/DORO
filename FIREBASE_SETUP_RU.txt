НАСТРОЙКИ FIREBASE ДЛЯ DORO

1. Firebase Console → Authentication → Sign-in method
   - Включить Anonymous (сайт использует анонимную сессию до входа).
   - Включить Email/Password (аккаунты DORO создаются через Firebase Auth).

2. Authentication → Settings → Authorized domains
   - Убедиться, что есть 9rei.github.io.
   - Если сайт открывается через собственный домен, добавить и его.

3. Firestore Database
   - Не удалять коллекции users, roles, payment_requests.
   - В документах users старые ID вида name__GROUP поддерживаются кодом совместимости; не удаляйте старые документы вручную до проверки миграции.
   - Если консоль показывает ошибку missing index, создать индекс по ссылке из сообщения Firebase для конкретного запроса.

4. Роль администратора
   - В коллекции roles должен быть документ, ID которого равен UID реального Firebase Auth аккаунта администратора (не имени пользователя, не ID профиля users и не UID анонимной сессии).
   - Поля документа: role = "admin"; subjects = [] (или нужный список для редактора).
   - После входа код пишет UID в Console с префиксом [roles].

5. Firestore Security Rules — КРИТИЧНО
   - Файл правил не был приложен к архиву, поэтому нельзя безопасно заменить правила вслепую.
   - Не используйте allow read, write: if true.
   - Убедитесь, что обычный пользователь не может изменять premiumActive/premiumExpiresAt в чужом документе users и не может одобрять payment_requests.
   - Для надёжной защиты активацию/отзыв Golden следует выполнять серверной Cloud Function, которая проверяет admin custom claim. Клиентская проверка роли нужна только для интерфейса и сама по себе не защищает базу.
   - Перед изменением Rules сохраните текущую версию и проверьте её в Emulator/на тестовом проекте. Если пришлёте текущие Rules, можно подготовить точный вариант без догадок.

6. После публикации проверить
   - Регистрация нового пользователя.
   - Вход существующего пользователя с правильным паролем и обработка неверного пароля.
   - Старый профиль с ID name__GROUP.
   - Golden: активная подписка, истёкшая подписка, явный отзыв в админке, отсутствие premiumActive в старом документе, временный сбой сети.
   - Список пользователей и админская панель.
